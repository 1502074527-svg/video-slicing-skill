# 踩坑记录（8 条血泪教训）

> 这些坑我们都踩过，每个都浪费了至少半天才定位到。
> 开源版本只列**通用性最强**的 8 条，更细的坑在内部迭代版本里。

## 1. SRT 时间码解析

**症状**：`int("04,800")` 把毫秒吃掉，时间戳全乱。
**根因**：SRT 时间码 `00:00:04,800` 里的 `,800` 是毫秒，不是小数。
**正解**：一律按**小数位数**归一——3 位是毫秒（`/1000`），6 位是微秒（`/1000000`）。

## 2. 切点表改了但旧切片还在

**症状**：改完切点表重新跑，发现视频内容与表格错位（曾缺 134 秒）。
**根因**：切片脚本只按名字判断文件是否存在，存在就跳过。
**正解**：按**真实时长**校验旧切片，与切点表偏差 >0.5s 强制重切。

## 3. 按字数等比拆长句

**症状**：半句一屏、时间靠猜，字幕腰斩语义。
**正解**：句末标点分句 + 就近标点断 + 跨静音强制断条（详见 [subtitle-segmentation.md](subtitle-segmentation.md)）。

## 4. 静音被并进字幕

**症状**：讲者停顿 17.7 秒想下一句，字幕一直挂着上一句，极违和。
**正解**：相邻两字间隔 ≥1.2s 视为静音，**强制断条**，不跨静音合并。

## 5. 去语气词列表过宽

**症状**：把「好」「这个」「就是」都当口水词删，「很好」→「很」，语义全改。
**正解**：`FILLER` 列表只放**真正的口水音**（啊、呃、嗯、那个），其他留给 LLM 判。

## 6. 漏字类错误 LLM 与拼音都抓不到

**症状**：「才下地」实为「才下地狱」（漏「狱」），上下文还通顺。
**根因**：漏字不是错字，拼音匹配和术语替换都抓不到。
**正解**：两条路——① **通读**（人工）；② **双通道对照**（Whisper + 领域 Prompt 做对照组，抓漏字类最灵）。

## 7. 经典排比被当成口吃

**症状**：《中庸》「有弗学，学之弗能弗措也」被清理脚本删成「有弗学，之弗能弗措也」。
**根因**：去重复规则把经典排比误判为讲者口吃。
**正解**：经典原文设**守卫名单**，清理前先比对，是经典原文就不许删。

## 8. LLM 自作主张删语气词

**症状**：让 LLM 校对，它顺手把「这个」「就是」全删了，后处理环节没法做精确清理。
**根因**：Prompt 没禁止，LLM 默认认为「校对 = 润色」。
**正解**：Prompt 里**明确禁止**删语气词——「一个字都不许少，后面环节自动去」。参考 [prompts/proofreader-confucian.md](prompts/proofreader-confucian.md)。

---

## 通用原则（从坑里归纳的）

1. **时间轴与文本分离**：所有替换/清理只动文本，时间戳只信字级。
2. **LLM 只提建议**：任何自动合入都要能追溯、可回滚。
3. **保留中间产物**：每一步的输入输出都存盘，出问题回到上一步改完再跑。
4. **人工把关是最后的防线**：再智能的自动化也得有人审。
