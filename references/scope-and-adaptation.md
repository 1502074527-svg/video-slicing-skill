# 场景范围与适配规范

> 本文件是 video-slicing-skill 的**边界法**：规定这套 Skill 只服务三个固定大场景，以及场景内部允许怎样适配。
> 任何流程、参数、文档改动与本文冲突的，以本文为准。

---

## 1. 三个固定大场景

| 编号 | 场景 | 一句话定义 | 核心交付 |
|---|---|---|---|
| **S1** | 口播 | 以讲者口述为主的长音视频，要把口语整理成可读、可发布的成稿 | 干净口播稿（保留时间戳） |
| **S2** | 字幕 | 已有视频需要逐字对齐、语义不断裂的字幕 | 精确字幕 SRT |
| **S3** | 高光剪辑 | 从长录播中挑出可独立发布的知识点片段 | 切片 mp4 + 每条配套字幕 + 切点表 |

**固定含义**：这三个是 Skill 的能力边界，不是可选项。

- 三个场景之外的需求一律不接，明确告知用户超出范围。
- 不因用户要求临时发明第四个场景（实时直播切片、多语言配音、自动配乐等），这类需求走第 6 节扩展流程。

---

## 2. 场景判定（路由）

判定只看**用户要什么产物**，不看素材是什么。同一个录播可以导出三种产物。

| 用户的说法 | 归入场景 |
|---|---|
| 「整理成文字稿」「去掉口头语」「我要讲稿」 | S1 口播 |
| 「加字幕」「重新做字幕」「字幕对不上」 | S2 字幕 |
| 「剪几条短视频」「挑出精彩片段」「这段拿去做抖音」 | S3 高光剪辑 |

规则：

- **命中多个场景时按依赖顺序执行：S2 → S1 → S3。** 字幕是时间轴基础，口播稿是选段依据。
- 判定不确定时，问用户要哪个产物，不猜。
- 用户只给视频、没说要什么，先问产物形态，再进场景。

---

## 3. 每个场景的固定骨架

四个环节缺一不可：**① 摸底 → ② 取时间轴 → ③ 出稿 → ④ 人工确认**。
场景差异只体现在 ③ 的加工方式和 ④ 的确认对象。

### S1 口播

| 项 | 内容 |
|---|---|
| 输入 | 音视频 |
| 取时间轴 | 字级 ASR |
| 出稿链 | `merge_srt` → `proofread`（术语替换）→ `clean_oral`（去口水词） |
| 交付 | 可读口播稿，每段带起止时间 |
| 必停点 | ① 术语表确认 ② 口播稿人工定稿 |
| 禁止 | 为句子通顺而改写讲者观点、合并不同句子改变原意 |

### S2 字幕

| 项 | 内容 |
|---|---|
| 输入 | 视频 + 已定稿文本 |
| 取时间轴 | 字级 ASR（唯一金标准） |
| 出稿链 | `build_subtitles --mode <sentence\|clause\|fragment>` |
| 交付 | SRT（帧边界吸附） |
| 必停点 | ① 断句模式选择 ② 单条字数/时长上限确认（按平台） |
| 禁止 | 用句级时间戳做字幕、跨静音并条、按字数等比硬拆 |

### S3 高光剪辑

| 项 | 内容 |
|---|---|
| 输入 | 视频 + 已完成的精确字幕 |
| 前置依赖 | **S2 必须已完成** |
| 出稿链 | 生成切点表 → 人工确认 → ffmpeg 切片 |
| 交付 | 切片 mp4 + 每条切片对应字幕 + 切点表 |
| 必停点 | ① 切点表人工确认（30 秒–5 分钟、语义完整、切点卡在相邻字幕条间隙） |
| 禁止 | 截断完整语句、切点落在字中间、无字幕依据凭感觉切 |

## 4. 允许的适配（场景内参数化）

以下维度**允许**按用户情况适配，且必须问用户、不得默认：

| 适配维度 | 取值 | 影响 |
|---|---|---|
| 领域 | 儒学 / 医学 / 法律 / 编程 / 通用 | 词表 + 校对 Prompt |
| ASR 方案 | A 剪映 / B whisper.cpp / C 火山方舟 | 精度、成本、标点 |
| 断句模式 | sentence / clause / fragment | 字幕节奏 |
| 目标平台 | B 站 / 视频号 / 小红书 / 抖音 | 时长上限、单条字数 |
| 词表来源 | 自带 / 用户提供 / 自动起草 | 术语准确率 |

以下维度**不允许**适配（红线，任何场景都不例外）：

| 不可变项 | 原因 |
|---|---|
| 时间轴必须来自字级时间戳 | 句级时间戳会漂移，直接导致字幕错位 |
| 文本最终决定权必须是人 | LLM 改字幕等于篡改讲者原话 |
| 每次自动替换必须可追溯、可回滚 | 出问题要能退到上一步 |
| 词表回写必须人工确认 | 防止单字规则污染全库 |

## 5. 约束条款（硬性）

| 编号 | 条款 | 说明 |
|---|---|---|
| **C1** | 单场景原则 | 一次任务只处理一个场景；混合需求拆成多次任务分别确认 |
| **C2** | 依赖原则 | S3 不得在 S2 完成前开工；S1 的输出可作为 S3 的选段依据，但不替代字幕 |
| **C3** | 铁律优先 | 三条铁律（字级时间轴 / 人工校对 / 可追溯）高于任何场景适配 |
| **C4** | 不可静默降级 | 字级时间戳拿不到时，停下告知用户，不得悄悄改用句级或估算时间 |
| **C5** | 可回滚 | 每个中间产物落盘为纯文本（SRT/TSV/MD），任何一步可单独重跑 |
| **C6** | 不越界 | 超出 S1–S3 的需求明确拒绝，并给出替代建议，不硬做 |

## 6. 扩展流程（新增场景）

确需新增场景时，按顺序走完四步，缺一步都不许开工：

1. **提出**：说明新场景要解决什么、交付什么。
2. **说明不可复用原因**：为什么 S1–S3 的骨架无法覆盖，而不是换个参数就能做。
3. **用户书面确认**：在对话中明确同意。
4. **更新本文件**：加场景表行 + 骨架 + 条款，并把版本号加一。

未更新本文件前，任何"临时新场景"都不得执行。

---

## 7. 开工自检清单

每次接活前，Agent 必须能回答这四个问题：

- [ ] 这个需求落在 S1 / S2 / S3 哪一格？答不上就说明没判定清楚，先问用户。
- [ ] 依赖的前置场景完成了吗？（S3 依赖 S2）
- [ ] 这次要适配哪些参数？问过用户了吗？
- [ ] 有没有任何一处触碰第 4、5 节的红线？

四问有一问答不上，不许进入执行。
